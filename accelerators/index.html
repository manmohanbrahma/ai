Inside a modern accelerator

SMs and CUDA cores

SM / CU architecture

Stream multiprocessors (NVIDIA) and compute units (AMD) are the basic compute tiles. Each SM contains 128 CUDA cores (Ampere GA102) or 64 FP32 lanes (RDNA3 Navi 31). Tensor cores (3rd‑gen on Ampere, 5th‑gen on Blackwell) accelerate matrix‑FP16/BF16/FP8 operations; AMD's AI accelerators provide similar throughput via WMMA and ROCm kernels.

Memory: the real constraint

HBM vs GDDR

Bandwidth and capacity

High‑Bandwidth Memory (HBM2e/HBM3/HBM3e) stacks die‑through‑via to deliver extreme bandwidth near the GPU die. GDDR6/GDDR6E/GDDR7 sits on the PCB and is cost‑effective for workstation cards. The memory wall — compute grows ~3× per generation while memory bandwidth grows ~1.5× — means serving throughput is often limited by how fast weights and KV cache can be streamed, not by peak TFLOPS.

Interconnect: scale‑up vs scale‑out

PCIe / NVLink / Infinity Fabric

Busses that move data

PCIe Gen5 x16 ≈128 GB/s bidirectional (64 GB/s each way). NVIDIA NVLink 4 provides 900 GB/s within a scale‑up domain; NVLink 5 doubles to 1.8 TB/s. AMD Infinity Fabric on MI300X offers 896 GB/s across the chiplet package. Scale‑out uses InfiniBand NDR 400 Gb/s or RoCE‑v2 / Ultra Ethernet; tensor‑parallel work across domains incurs latency overhead, so keep TP inside a scale‑up domain when possible.

What inference actually demands

Prefill vs decode

Two phases, two bounds

Prefill processes the entire prompt in parallel; it is compute‑bound (high arithmetic intensity ≈ thousands of FLOP/byte). Decode generates one token at a time, repeatedly reading weights and KV cache from memory; it is memory‑bandwidth‑bound. Rules of thumb:

  • Single‑stream decode tok/s ≈ HBM bandwidth ÷ (weights‑GB + KV‑per‑token‑GB)
  • Prefill tok/s ≈ compute TFLOPS × MFU% ÷ (2 × params‑per‑token)

Where this is heading

Roadmap

Near‑term and long‑term trends

  • HBM4 and LPDDR‑tier memory (Crescent Island‑style 160 GB LPDDR5x for inference‑only ASICs)
  • FP4/FP6 native matrix cores; MLA / KV compression reduces KV‑bytes/token 4‑9× (DeepSeek‑V3 MLA: ~35 KB/token FP16 vs ~320 KB for Llama‑3‑70B)
  • Speculative decoding, continuous batching, PagedAttention, disaggregated prefill/decode (e.g. NVIDIA Dynamo‑style)
  • Silicon‑photonic co‑packaged optics for scale‑out; CXL‑based memory pooling in 2026‑2027
