Installation Guide

Single-Node Run:ai Installation

One command line, oif, installs open-source NVIDIA Run:ai 3.0 on an Ubuntu GPU server in about 30 minutes: Kubernetes, the NVIDIA GPU Operator, Prometheus, ingress, a domain, TLS, the Run:ai control plane and cluster, and a quota test. This guide walks through it from an empty host to the Run:ai UI; planning decisions are in the companion Deployment Guide.

Author Manmohan BrahmaOctober 2026Run:ai 3.0.20Kubernetes 1.35.9GPU Operator 26.7.1oif on GitHubDeployment GuideAll guides

1What you get

From an empty Ubuntu server to open-source Run:ai 3.0.20 scheduling GPU workloads, with one command line, oif:

  • single-node Kubernetes 1.35 with Calico, local-path storage and MetalLB;
  • the NVIDIA driver and the NVIDIA GPU Operator;
  • Prometheus, Grafana and Alertmanager;
  • the HAProxy ingress controller, a domain that needs no DNS server, and TLS from a private CA;
  • the Run:ai control plane and cluster, connected, with projects and GPU quotas.

Every change to the host is recorded, and oif uninstall reverses it. Planning topics (architecture, versions, sizing, network, security) are in the companion Deployment Guide.

Everything shown here is from a real installation on the reference host: Ubuntu 26.04.1 and an NVIDIA RTX A6000. Addresses and the host name are shown as placeholders.

2Before you start

  • Ubuntu 22.04, 24.04 or 26.04 on the server; at least 16 CPU threads, 64 GB memory and 150 GB free under /var/lib
  • An NVIDIA GPU, Ampere or newer
  • A user with sudo that you log in as over SSH
  • 2 to 5 free IP addresses on the server's subnet for MetalLB
  • Outbound HTTPS to the registries (registry.k8s.io, nvcr.io, ghcr.io, quay.io, docker.io), github.com, helm.ngc.nvidia.com and the Ubuntu archive
  • One reboot of the server is acceptable

No NVIDIA NGC key is needed: open-source Run:ai images and charts are public.

3How oif works

oif is a Bash command line in the public repository manmohanbrahma/open-inference-fabric. It installs in stages; each stage is skipped once done, so running oif install again continues where it stopped and changes nothing that is finished. A stage tied to a version in versions.env runs again when that version changes.

CommandChanges the hostWhat it does
./oif checknohost and GPU report, DNS and registry reachability
sudo ./oif installyesasks the missing settings, shows a summary, then runs as a background job
sudo ./oif install --reconfigureyesasks again for settings that are invalid or changed in .env
sudo ./oif statusnofinished stages and recorded host changes
sudo ./oif plannowhat uninstall would remove and keep
sudo ./oif uninstallyesreverses every recorded change; asks you to type wipe

The stages, in order:

GroupStages
Hostpreflight, host-packages, kernel, containerd, nvidia-driver, reboot, host-verify
Kubernetesk8s-packages, kubernetes, k8s-tokens, calico, storage, metallb, k8s-verify
NVIDIAgpu-operator, gpu-verify
Around Run:aiprometheus, ingress, pki, runai-dns
Run:airunai, runai-fractions, runai-verify, runai-quota

4Download and configure

1. Download the code

Git is not needed:

cd ~
wget -qO oif.tar.gz https://github.com/manmohanbrahma/open-inference-fabric/archive/refs/heads/main.tar.gz
tar -xzf oif.tar.gz && mv open-inference-fabric-main open-inference-fabric && rm oif.tar.gz
cd ~/open-inference-fabric
./oif version

2. Check the host

The check only reads; it does not need sudo.

./oif check
GPU lineMeaning
NVIDIA ... computeused by Kubernetes from this guide on
other ... ignoredfor example the server management controller's display chip; never touched

3. Write the settings

cp .env.example .env
chmod 600 .env
nano .env
SettingWhat to enter
HOST_IPthe server's main address
METALLB_RANGEfree addresses on the same subnet, first-last; the first one becomes the Run:ai address
INSTALL_DIRdata folder on a large disk, for example /data/oif; removed by uninstall
NVIDIA_GPUSempty for all NVIDIA GPUs, or PCI addresses from the NVIDIA lines
RUNAI_DOMAINempty for runai.<first-MetalLB-address>.sslip.io, or your own domain
GRAFANA_ADMIN_PASSWORD12 characters or more; or leave empty and type it at the prompt
HF_TOKENonly for gated Hugging Face models; empty is fine

Values in .env are read as data, never run as a script. A GPU listed under the wrong vendor is refused with the reason.

5Install: host preparation

sudo ./oif install

oif asks for every missing setting first, with passwords hidden, shows a summary, and asks whether it may reboot the host by itself. Answer y to both. From then on the install runs as a background job: a dropped SSH session does not stop it.

The host reboots once. Log in again after about two minutes and follow the log; reading it needs no sudo:

tail -f /var/log/oif-install.log
Host changeReversed by uninstall
Packages: conntrack, curl, ipset, socat, containerd, runc, NVIDIA 595-server headless driver and utilitiespurged, unless the OS depends on one
/etc/modules-load.d/90-oif.conf, /etc/sysctl.d/90-oif.confdeleted
Swap line in /etc/fstab commented outrestored from its backup
/etc/containerd/config.toml (systemd cgroups, data on the data disk)deleted
/etc/modprobe.d/90-oif-nouveau.conf (nouveau blocked)deleted, boot image rebuilt

6Install: Kubernetes

The same sudo ./oif install continues; nothing is asked. It installs Kubernetes 1.35.9 from the official package repository, runs kubeadm init with address ranges that do not overlap the host's networks, removes the join tokens, then installs Calico, local-path storage and MetalLB, and proves them with a test volume and a test web server on the first MetalLB address.

kubectl works for your own user without sudo:

kubeadm's own output contains a join token and a certificate key. oif keeps it in /var/lib/oif/kubeadm-init.log (root only), deletes the tokens (a single node needs none) and shows <redacted> in the readable log.

7Install: NVIDIA GPU Operator

The GPU Operator v26.7.1 installs with its default stack (container toolkit, device plugin, GPU feature discovery, DCGM exporter, Node Feature Discovery) on the host's driver. oif then runs a pod that executes nvidia-smi and NVIDIA's CUDA vectorAdd sample, and reads the GPU's metrics.

Run:ai expects these before it is installed:

9Install: Run:ai

oif downloads runai-installer 3.0.20, checks it against the published SHA-256, writes its configuration (control plane and cluster on this cluster, GPU Operator and Prometheus already installed, ingress class haproxy, the certificate and CA), runs the preflight checks, then installs.

The configuration oif generates, with your domain and certificate paths filled in:

install:
  mode: full_installation
  connectivity: connected
registry:
  type: ngc                             # open source: public images, no credentials
tls:
  certPath: /var/lib/oif/pki/tls.crt
  keyPath: /var/lib/oif/pki/tls.key
  caChainPath: /var/lib/oif/pki/ca.crt
controlPlane:
  enabled: true
  version: "3.0.20"
  domain: runai.<lb-ip>.sslip.io
cluster:
  enabled: true
  version: "3.0.20"
  name: oif
  workloadRouting: host
prerequisites:
  gpuOperator:
    mode: skip
  prometheus:
    mode: skip
  networkOperator:
    mode: skip
features:
  skip: true
externalConnection:
  type: ingress
  ingress:
    className: haproxy

Then oif keeps Run:ai's GPU-fraction daemons off the GPU node while its driver is older than r615 (Run:ai 3.0's minimum for fractions), and verifies the result.

10Open the Run:ai UI

1. Read the administrator login

Run:ai generates the first administrator. Only root can read the password:

sudo kubectl --kubeconfig /etc/kubernetes/admin.conf -n runai-backend get configmap runai-backend-tenants-manager -o jsonpath='{.data.ADMIN_USERNAME}'; echo
sudo kubectl --kubeconfig /etc/kubernetes/admin.conf -n runai-backend get secret runai-backend-gen-tenants-manager -o jsonpath='{.data.ADMIN_PASSWORD}' | base64 -d; echo

2. Reach the load-balancer address

If your computer is on the server's network, open https://runai.<lb-ip>.sslip.io directly. If you reach the server only through a VPN that routes the server's own address, use an SSH SOCKS tunnel and a browser that sends its traffic and its DNS lookups through it:

ssh -N -D 127.0.0.1:11080 <user>@<host-ip>

On Windows, start Chrome with a separate profile that uses the tunnel:

"C:\Program Files\Google\Chrome\Application\chrome.exe" --user-data-dir=%TEMP%\chrome-runai --proxy-server=socks5://127.0.0.1:11080 --host-resolver-rules="MAP * ~NOTFOUND , EXCLUDE 127.0.0.1" https://runai.<lb-ip>.sslip.io/

3. Trust the oif CA

Copy ~/oif-ca.crt from the server and import it once: in Windows, double-click it, Install Certificate, Local Machine (or Current User), Place all certificates in the following store, Trusted Root Certification Authorities. Chrome and Edge use that store. On macOS, open it in Keychain Access and set it to Always Trust. Firefox has its own store: Settings, Privacy & Security, Certificates, View Certificates, Authorities, Import.

scp <user>@<host-ip>:oif-ca.crt .

4. Log in

Sign in with the administrator from step 1, then change its password after the first login.

12Projects and the quota test

The last stage, runai-quota, proves that Run:ai's quotas are enforced, through the Run:ai REST API:

  1. It logs in as the administrator (credentials stay in memory, never printed).
  2. It creates project team-a with a quota of 1 GPU, and team-b with 0 GPUs and over-quota off.
  3. team-b submits a pod asking for one GPU while the GPU is free: it must stay Pending. The quota holds it, not a lack of capacity.
  4. team-a submits the same pod: it must run on the GPU, while team-b's still waits.
  5. The test pods are deleted; the projects stay.

The pod used by the test, in a Run:ai project's namespace:

apiVersion: v1
kind: Pod
metadata:
  name: gpu-quota-test
  namespace: runai-team-a
spec:
  schedulerName: runai-scheduler
  runtimeClassName: nvidia
  restartPolicy: Never
  containers:
    - name: gpu
      image: nvcr.io/nvidia/k8s/cuda-sample:vectoradd-cuda12.5.0
      command: ["sh", "-c", "nvidia-smi -L && sleep 600"]
      resources:
        limits:
          nvidia.com/gpu: 1

What the pod sees

nvidia-smi runs inside the workload too: the NVIDIA container toolkit injects it with the device files of the one GPU the pod was given. The first pod in [platform/runai/smi-pods.yaml](https://github.com/manmohanbrahma/open-inference-fabric/blob/main/platform/runai/smi-pods.yaml) shows it in project team-a:

set -a; . ./versions.env; set +a
NS=runai-team-a envsubst < platform/runai/smi-pods.yaml | awk '/^---/{exit} {print}' | kubectl apply -f -
kubectl -n runai-team-a logs smi-nvidia
kubectl -n runai-team-a delete pod smi-nvidia

13Troubleshooting

ProblemCause and fix
./oif check: DNS server ... does not answerA DNS server in the host's settings refuses queries. The host's resolver falls back to the next one, but Kubernetes' DNS does not, so pods see random lookup failures. Remove it from the host's network settings (netplan). oif's cluster DNS answers the Run:ai domain itself either way.
Run:ai cluster chart: job pre-install failed: BackoffLimitExceededIts pre-install job could not resolve the control plane domain (kubectl -n runai logs job/pre-install). The runai-dns stage fixes it; run sudo ./oif install again. oif removes the failed job before retrying.
gpu-fractioning-mpsd in CrashLoopBackOffThe NVIDIA driver is older than r615. The runai-fractions stage keeps the fraction daemons off the node; run sudo ./oif install.
Node shows Missing Prerequisites in Run:aiSame cause, GPU fractions only; whole GPUs work.
Browser: ERR_NAME_NOT_RESOLVEDThe browser resolves names locally: use the --host-resolver-rules setting so DNS goes through the tunnel, or make sure your computer can resolve sslip.io.
Browser: certificate warningImport oif-ca.crt into the trusted root authorities (Ingress and UI use the oif certificate).
the saved settings are not valid on this hostsudo ./oif install --reconfigure; only invalid values are asked again.
An install stage failedFix the cause shown and run sudo ./oif install again: finished stages are skipped. The Run:ai installer's own logs are in /var/lib/oif/runai/.

14Uninstall

Preview, without changing anything:

sudo ./oif plan

Remove everything oif installed and return the host to its OS default (Kubernetes, Run:ai, the GPU Operator and its containerd and CDI files, packages, kernel settings, swap, the data folder):

sudo ./oif uninstall

It asks you to type wipe, offers to reboot at the end, and runs as a background job. Only packages oif installed are removed, never one the operating system had before.
